## Long Term Goals
This role is a **full-stack AI product engineer**—you’ll turn research experiments into polished, scalable software end-to-end. Studying for it means deliberately combining three streams: **backend/AI serving (Python)**, **frontend interfaces (JavaScript)**, and **production engineering for ML**. Below is a structured way to prepare.

---

## 1. Break down the role into concrete skills

| Area                            | What you actually need to do                                                                                                                                                             |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Python backend & middleware** | Build APIs (FastAPI/Flask), wrap ML models, handle async tasks, integrate with message queues, manage concurrency.                                                                       |
| **AI model serving**            | Take a model from a researcher’s notebook and make it run behind an endpoint with batching, streaming, GPU utilization, and low latency.                                                 |
| **JavaScript frontend**         | Create reactive UIs that consume AI predictions, handle real-time streaming (WebSockets, SSE), and provide great UX around ML features (loading states, error handling, feedback loops). |
| **Production reliability**      | Containerisation (Docker), orchestration (Kubernetes basics), CI/CD, monitoring, logging, scaling strategies.                                                                            |
| **Collaboration with research** | Read and refactor research code, enforce reproducibility (environments, experiment tracking), translate prototypes into well-tested services.                                            |

---

## 2. Study roadmap (build this order)

### Phase 1 – Strengthen core foundations (1–2 months)
*If you’re already solid here, compress or skip.*

- **Python** (advanced level): decorators, generators, `asyncio`, type hints, `pydantic`, context managers.
- **JavaScript** (modern): ES6+, promises/async-await, modules, event loop, basic TypeScript.
- **Backend web framework**: Build REST APIs with **FastAPI** (Python) and **Express** (Node) to understand both paradigms.
- **Frontend basics**: Learn **React** (with hooks) – it’s the most common choice for AI dashboards. Grasp components, state management, and effects.
- **Databases & caching**: PostgreSQL (via SQLAlchemy/asyncpg), Redis (caching, queues).
- **Containerisation**: Dockerise a simple Python API and a React app; use Docker Compose.

### Phase 2 – AI model serving & middleware (2–3 months)
This is the heart of the role.

- **Wrapping ML models**: Start with a PyTorch or Hugging Face model. Write a FastAPI endpoint that loads the model, runs inference, and returns JSON.  
  *Key skills*: model loading/unloading, warm-up, GPU memory management, converting notebooks to modules.
- **Asynchronous & heavy task handling**: Use `BackgroundTasks`, Celery + Redis, or ARQ to offload long-running inference. Learn to return a `task_id` and poll for results.
- **Performance & optimisation**:
  - Convert models to TorchScript or ONNX; try TensorRT for GPU speedups.
  - Implement dynamic batching (e.g., with NVIDIA Triton, TorchServe, or a custom batching layer).
  - Explore streaming responses with `StreamingResponse` in FastAPI (for LLM token-by-token output).
- **Message queues & event-driven patterns**: Play with RabbitMQ or Kafka. Build a pipeline: frontend request → API → queue → worker (model) → result stored → frontend notified.
- **Middleware patterns**: Write a simple API gateway that handles authentication, rate limiting, and routing to multiple models. Use something like `traefik` or `nginx` in Docker Compose to get comfortable.

### Phase 3 – Frontend for AI interfaces (1–2 months)
Focus on patterns specific to AI products.

- **Streaming responses**: Build a chat UI in React that receives SSE (Server-Sent Events) from a FastAPI streaming LLM endpoint. Show tokens as they arrive.
- **File upload & progress**: Create an upload component for images/documents, show progress bars, handle validation, and display AI-generated results (e.g., object detection boxes drawn on canvas).
- **Real-time data**: Use WebSockets (via `socket.io` or raw) to push model status updates or live predictions from a backend worker.
- **State management for async flows**: Use React Query / TanStack Query, or SWR to manage cache, polling, and optimistic updates from your AI APIs.
- **Dashboard building**: Integrate a charting library (Recharts, D3) to visualise metrics, model performance, or A/B test results.

### Phase 4 – Production scalability & MLOps (ongoing, but 1–2 months deep dive)
This is what separates a prototype from a “highly scalable” system.

- **Container orchestration**: Learn Kubernetes basics (pods, deployments, services, ingress). Deploy your FastAPI + React stack with `minikube` or `kind`.
- **CI/CD for ML**: Set up GitHub Actions to run tests, build Docker images, and deploy. Write tests for model pipelines (input/output shapes, latency budgets).
- **Experiment tracking & reproducibility**: Use MLflow or DVC to track model versions and parameters. Package the research code so that any team member can reproduce an experiment with a single command (e.g., `dvc repro`).
- **Observability**: Add structured logging (JSON logs), Prometheus metrics (request duration, queue length, GPU utilisation), and tracing.
- **Scaling strategies**: Understand horizontal scaling with replicas, auto-scaling based on queue depth, GPU node pools, and model caching layers.
- **Security basics**: Input sanitisation, environment variables, API authentication (JWT), avoiding prompt injection in LLM apps.

### Phase 5 – End-to-end capstone projects (build 2–3)
Projects that prove you can do the whole stack. These are your portfolio.

**Project ideas:**
- **AI Chat with RAG**: React chat UI ↔ FastAPI ↔ LLM + vector database (ChromaDB/Pinecone). Add streaming, conversation history, citation highlighting. Dockerise the whole thing with a GPU-capable setup.
- **AI Image Generator with Queue**: Users submit prompts → task queued in Redis/Celery → Stable Diffusion worker → result stored in S3 (MinIO locally) → frontend polls and displays the image. Add batching and a gallery.
- **Take a research notebook and productise it**: Find an interesting paper with code (e.g., on GitHub). Wrap it in a FastAPI service, build a minimal UI to demo it, write a Dockerfile, add a health-check endpoint, and write a README explaining how you turned research into a reliable service.

## 3. Resources to use (curated)

### Python / Backend
- **FastAPI official tutorial** – the async and dependency injection parts are essential.
- **“Robust Python”** by Patrick Viafore – for clean, production-ready Python.
- **Test-Driven Development with Python** (the Django edition has good testing patterns transferable to FastAPI).

### AI Serving
- **Full Stack Deep Learning** (course, UC Berkeley) – focuses on the productisation of ML.
- **NVIDIA Deep Learning Institute** – free courses on Triton Inference Server, TensorRT.
- **Hugging Face documentation** on pipelines and `text-generation-inference` (TGI) – many companies use TGI or vLLM for LLM serving; study their architecture.
- **BentoML** docs – great example of a unified serving framework.

### JavaScript / Frontend
- **React official beta docs** (react.dev) – modern approach with hooks.
- **“Streaming UIs with JavaScript” patterns** – explore Vercel’s AI SDK for React (it shows how to elegantly handle streaming from an LLM).
- **Frontend Masters** or **Epic React** by Kent C. Dodds for deep React knowledge.

### Production / MLOps
- **“Designing Machine Learning Systems”** by Chip Huyen – the bible for production ML.
- **Made With ML** (madewithml.com) by Goku Mohandas – a complete end-to-end MLOps course.
- **Kubernetes in Action** – go through at least the first 10 chapters.
- **12 Factor App** methodology – apply it to your ML services.

### System Design for ML
- Practice designing a “real-time video processing pipeline” or “LLM-powered customer support system” using standard frameworks (draw architecture diagrams). Review the ML system design primer on GitHub (e.g., “machine learning system design”).

## 4. How to practise the “work closely with research” part

- Fork a research repository (e.g., from Papers with Code). Improve the code: add type hints, separate config from logic, create a CLI, write unit tests, add logging, containerise it. Document how to run and reproduce results.
- Contribute to open-source AI tools (LangChain, LlamaIndex, Hugging Face transformers). Even a small PR that improves error handling or adds a test will look impressive.
- Learn to read a paper and ask: “What would break at 1000 requests per second? How do I batch this? How do I handle cold start?”

## 6. Typical interview preparation for this role

You’ll likely face:
- **Coding**: Python algorithms + JS frontend problem (maybe building a small widget).
- **System design**: “Design an AI-powered real-time translation service” or “Build an endpoint that serves an LLM to millions of users.”
- **ML fundamentals**: Not always a deep theory test, but you must explain model loading, GPU memory, trade-offs of quantization, etc.
- **Practical take-home**: “Given this messy Python script that runs a model, turn it into a production service with a simple frontend in a weekend.”

So, as you study, constantly ask: *Am I building muscle in turning a raw model into a fast, reliable, and observable system that a user can actually interact with?*

**In short**: Aim to become the person who can take a researcher’s `.pth` file and a scribbled notebook and, within days, deliver a polished, scalable product. The study path above is exactly that – build, break, optimise, and repeat.
