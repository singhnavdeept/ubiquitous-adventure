## 1. DATA MODEL

### Keyspace

**Q1. Create a keyspace named `university` with replication factor 1.**

```sql
CREATE KEYSPACE university
WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 1};

USE university;
```

**Q2. Create a keyspace named `ecommerce` with NetworkTopologyStrategy for a datacenter named `dc1` with RF 2.**

```sql
CREATE KEYSPACE ecommerce
WITH replication = {'class': 'NetworkTopologyStrategy', 'dc1': 2};
```

**Q3. Alter an existing keyspace to change replication factor to 2.**

```sql
ALTER KEYSPACE university
WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 2};
```

**Q4. Drop a keyspace.**

```sql
DROP KEYSPACE university;
```

### Primary Key, Partition Key, Clustering Columns

**Concept:**

```
PRIMARY KEY (partition_key)                        -- simple primary key
PRIMARY KEY (partition_key, clustering_col1, ...)  -- composite key
PRIMARY KEY ((col1, col2), clustering_col)         -- compound partition key
```

- **Partition key** → determines which node stores the row
- **Clustering columns** → sort data within a partition (wide rows)
- **Wide row** → one partition key, many rows under it (like a folder with many files)

---

**Q1. Create a `students` table with `student_id` as the only primary key.**

```sql
CREATE TABLE students (
  student_id  INT PRIMARY KEY,
  name        TEXT,
  age         INT,
  department  TEXT
);
```

---

**Q2. Create a `courses` table where `department` is the partition key and `course_id` is a clustering column. This is a wide row — all courses of a department are in one partition.**

```sql
CREATE TABLE courses (
  department  TEXT,
  course_id   INT,
  course_name TEXT,
  credits     INT,
  PRIMARY KEY (department, course_id)
);
```

- All rows with `department = 'CS'` go to the same node
- Within that partition, rows are sorted by `course_id`

---

**Q3. Create an `orders` table with a compound partition key `(customer_id, year)` and clustering column `order_id` sorted descending.**

```sql
CREATE TABLE orders (
  customer_id INT,
  year        INT,
  order_id    UUID,
  amount      DOUBLE,
  status      TEXT,
  PRIMARY KEY ((customer_id, year), order_id)
) WITH CLUSTERING ORDER BY (order_id DESC);
```

---

**Q4. Create a `sensor_data` table — classic wide row example. Partition by sensor, cluster by timestamp.**

```sql
CREATE TABLE sensor_data (
  sensor_id   TEXT,
  recorded_at TIMESTAMP,
  temperature DOUBLE,
  humidity    DOUBLE,
  PRIMARY KEY (sensor_id, recorded_at)
) WITH CLUSTERING ORDER BY (recorded_at DESC);
```

> Every reading for a sensor is in one partition, newest first.

### Create Keyspace + Table (full example)

**Q1. Create a keyspace `school` and a `students` table inside it.**

```sql
CREATE KEYSPACE school

CREATE TABLE students (
  student_id  UUID PRIMARY KEY,

  age         INT,
  department  TEXT,
  email       TEXT,
  is_active   BOOLEAN,
  enrolled_on TIMESTAMP

```

```sql
CREATE TABLE employees (
  emp_id    UUID PRIMARY KEY,

  emails    SET<TEXT>,
  metadata  MAP<TEXT, TEXT>
);
```

### SELECT

**Q1. Select all students.**

```sql
SELECT * FROM students;
```

**Q2. Select specific columns.**

```sql
SELECT name, department, age FROM students;
```

**Q3. Select by primary key (most efficient).**

```sql
SELECT * FROM students WHERE student_id = <your-uuid-here>;
```

**Q4. Select from courses table by partition key.**

```sql
-- Uses partition key — fast, no ALLOW FILTERING needed
SELECT * FROM courses WHERE department = 'CS';
```

**Q5. Select with partition key + clustering column.**

```sql
SELECT * FROM courses WHERE department = 'CS' AND course_id = 101;
```

**Q6. Select with ORDER BY (only on clustering columns).**

```sql
SELECT * FROM sensor_data
WHERE sensor_id = 'sensor_01'
ORDER BY recorded_at DESC;
```

**Q7. Select with LIMIT.**

```sql
SELECT * FROM students LIMIT 5;
```

### FILTERING

**Q8. Filter on a non-primary-key column — requires ALLOW FILTERING.**

```sql
SELECT * FROM students WHERE age = 21 ALLOW FILTERING;
SELECT * FROM students WHERE department = 'CS' ALLOW FILTERING;
```

> `ALLOW FILTERING` tells Cassandra to scan all partitions. Fine for dev/exam, bad in production at scale.

**Q9. Filter with range on clustering column.**

```sql
-- All sensor readings between two timestamps
SELECT * FROM sensor_data
WHERE sensor_id = 'sensor_01'
AND recorded_at >= '2024-01-01 00:00:00'
AND recorded_at <= '2024-01-31 23:59:59';
```

### INDEXING

**Concept:** By default you can only WHERE on primary key columns. Secondary indexes let you WHERE on other columns without ALLOW FILTERING — but they're only good for low-cardinality columns (like department, status, boolean).

**Q1. Create a secondary index on `department`.**

```sql
CREATE INDEX ON students (department);
```

Now this works without ALLOW FILTERING:

```sql
SELECT * FROM students WHERE department = 'CS';
```

**Q2. Create a named index on `is_active`.**

```sql
CREATE INDEX idx_active ON students (is_active);

SELECT * FROM students WHERE is_active = true;
```

**Q3. Create index on a MAP key.**

```sql
CREATE INDEX ON employees (KEYS(metadata));

SELECT * FROM employees WHERE metadata CONTAINS KEY 'team';
```

**Q4. Drop an index.**

```sql
DROP INDEX idx_active;
```

> **Rule of thumb:** Index columns with few distinct values (department, status, boolean). Never index high-cardinality columns like email or UUID.

## 3. CASSANDRA ADMINISTRATION

### Compaction

**Concept:**

- When you write to Cassandra, data goes to **SSTables** (immutable files on disk)
- Updates and deletes don't overwrite — they write new SSTables with **tombstones**
- **Compaction** merges SSTables, removes tombstones, reclaims space, and improves read performance
- Runs automatically in the background

---

**Three compaction strategies:**

|Strategy|Use Case|
|---|---|
|**STCS** (SizeTieredCompactionStrategy)|Write-heavy workloads, default|
|**LCS** (LeveledCompactionStrategy)|Read-heavy workloads, low space amplification|
|**TWCS** (TimeWindowCompactionStrategy)|Time-series data (sensor, logs)|

---

**Q1. Check current compaction strategy of a table.**

```sql
DESCRIBE TABLE students;
-- look for compaction = {...} in the output
```

**Q2. Set LeveledCompactionStrategy on the students table (read-heavy).**

```sql
ALTER TABLE students
WITH compaction = {'class': 'LeveledCompactionStrategy', 'sstable_size_in_mb': '160'};
```

**Q3. Set TimeWindowCompactionStrategy on sensor_data (time-series).**

```sql
ALTER TABLE sensor_data
WITH compaction = {
  'class': 'TimeWindowCompactionStrategy',
  'compaction_window_unit': 'DAYS',
  'compaction_window_size': '1'
};
```

**Q4. Set SizeTieredCompactionStrategy back (write-heavy / default).**

```sql
ALTER TABLE students
WITH compaction = {'class': 'SizeTieredCompactionStrategy'};
```

**Q5. Trigger compaction manually (from terminal, not cqlsh).**

```bash
# inside Docker container
docker exec -it cassandra nodetool compact university students
# compact <keyspace> <table>
```

**Q6. Check compaction stats.**

```bash
docker exec -it cassandra nodetool compactionstats
```

**Q7. Check overall node health and disk usage.**

```bash
docker exec -it cassandra nodetool status
docker exec -it cassandra nodetool info
docker exec -it cassandra nodetool tablestats university.students
```

## Quick Reference — What Needs ALLOW FILTERING?

|Query|Needs ALLOW FILTERING?|
|---|---|
|WHERE on partition key|❌ No|
|WHERE on partition key + clustering column|❌ No|
|WHERE on secondary indexed column|❌ No|
|WHERE on any other column|✅ Yes|
|ORDER BY on non-clustering column|❌ Not supported at all|

## Common Exam Pattern — Full Workflow

```sql
-- 1. Create keyspace
CREATE KEYSPACE college
WITH replication = {'class': 'SimpleStrategy', 'replication_factor': 1};

USE college;

-- 2. Create table
CREATE TABLE students (
  dept        TEXT,
  student_id  INT,
  name        TEXT,
  age         INT,
  email       TEXT,
  PRIMARY KEY (dept, student_id)
) WITH CLUSTERING ORDER BY (student_id ASC);

-- 3. Insert
INSERT INTO students (dept, student_id, name, age, email)
VALUES ('CS', 1, 'Alice', 21, 'alice@example.com');

INSERT INTO students (dept, student_id, name, age, email)
VALUES ('CS', 2, 'Bob', 22, 'bob@example.com');

INSERT INTO students (dept, student_id, name, age, email)
VALUES ('Mech', 3, 'Charlie', 20, 'charlie@example.com');

-- 4. Select
SELECT * FROM students WHERE dept = 'CS';
SELECT * FROM students WHERE dept = 'CS' AND student_id = 1;

-- 5. Update
UPDATE students SET age = 23 WHERE dept = 'CS' AND student_id = 1;

-- 6. Delete column
DELETE email FROM students WHERE dept = 'CS' AND student_id = 2;

-- 7. Delete row
DELETE FROM students WHERE dept = 'CS' AND student_id = 2;

-- 8. Index + filter
CREATE INDEX ON students (age);
SELECT * FROM students WHERE age = 21;

-- 9. Compaction
ALTER TABLE students
WITH compaction = {'class': 'LeveledCompactionStrategy'};
```
